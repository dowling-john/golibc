# golibc

[![CI](https://github.com/dowling-john/golibc/actions/workflows/ci.yml/badge.svg)](https://github.com/dowling-john/golibc/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/dowling-john/golibc/pkg/golibc.svg)](https://pkg.go.dev/github.com/dowling-john/golibc/pkg/golibc)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**A C standard library written in pure Go.** It talks to the Linux kernel through raw system calls. There is no cgo, no libc, and not a single third-party module.

Programs built on it compile with `CGO_ENABLED=0` into one static binary that needs **nothing installed on the target system** except a kernel: no shared libraries, no system prep, nothing to drift out of sync.

```go
package main

import (
	"github.com/dowling-john/golibc/pkg/golibc"
)

func main() {
	golibc.Printf(golibc.CStr("hello from golibc, pid %d\n"), golibc.Getpid())
	golibc.Printf(golibc.CStr("pi=%.5f  hex=%#x  [%-6s]\n"), golibc.M_PI, 48879, golibc.CStr("ab"))
	golibc.Exit(0) // flushes stdio
}
```

```console
$ CGO_ENABLED=0 go build -o hello . && file hello
hello: ELF 64-bit LSB executable, ARM aarch64, statically linked
$ ./hello
hello from golibc, pid 1
pi=3.14159  hex=0xbeef  [ab    ]
```

## Why

- **No fragile installs.** Cgo ties a binary to the C toolchain and shared libraries on the machine that builds and runs it. golibc binaries are self-contained and cross-compile with a plain `GOOS`/`GOARCH`.
- **A libc you can read.** Every function is a few lines of Go over a thin syscall layer, which makes it a good base for freestanding programs, code transpiled from C, and learning how libc works.
- **Checked against the real thing.** `printf`, `scanf`, `strftime` and the time-zone functions are tested against output generated by glibc, not against what the author remembers it does.

## Install

```sh
go get github.com/dowling-john/golibc/pkg/golibc
```

Requires Go 1.23+ and Linux (`amd64` or `arm64`). See [Platform support](#platform-support).

Naming follows C with an initial capital: `strlen` is `Strlen`, `fopen` is `Fopen`. Strings are NUL-terminated `*byte`, memory is `unsafe.Pointer`, and failures return `-1` (or `nil`) with the reason available from `GetErrno()`.

### printf

Supports the flags `- + space # 0`, field width and precision (including `*`), the length modifiers `hh h l ll z j t`, and the conversions `d i u o x X c s p f F e E g G %`. Arguments are ordinary Go values:

- Each integer keeps its own Go width. `int32(-1)` printed with `%u` gives `4294967295`, and `int(-1)` gives `18446744073709551615`, unless a length modifier says otherwise.
- `%s` takes a C string (`*byte`) or a Go `string`, and prints `(null)` for a nil pointer.
- `%f`, `%e` and `%g` take `float32` or `float64`.
- Not supported: `%n`, `%a`, wide characters, and positional arguments (`%1$d`).

### scanf

`Sscanf`, `Fscanf` and `Scanf` take pointers to the destinations, and the pointer type decides the width, so length modifiers are accepted and ignored. Supported: `%d %i %u %o %x %X`, `%f %e %g`, `%s`, `%c`, `%[set]`, `%n`, `%*` suppression, widths, and literal and whitespace matching. `%s` and `%[` write into a `*byte` C buffer (size it yourself, as in C) or into a `*string`. Return values, including the EOF cases and glibc's partial `%c` read, are checked against glibc.

### Sockets and waiting

Where C passes a `struct sockaddr` and a length, golibc takes and returns a `Sockaddr` value: `*SockaddrIn`, `*SockaddrIn6`, `*SockaddrUn` (a leading NUL byte means an abstract socket) or `*SockaddrNl` (netlink). `Accept` returns the peer address, `Getsockname`/`Getpeername` return the address, and `Recvmsg`/`Sendmsg` carry ancillary data, so passing file descriptors (`UnixRights`) and peer credentials (`UnixCredentials`) works. Blocking calls block the calling goroutine's OS thread, not the whole program.

`Poll`, `EpollWait`, `Select` and `Nanosleep` never return `EINTR`. The Go runtime signals its own threads for scheduling, and these calls are never restarted by the kernel, so a C-style `EINTR` would show up in programs that never installed a signal handler. Interrupted waits resume with the time remaining instead, as the standard library does. `FD_SET` panics with a clear message for a descriptor of 1024 or more (where C corrupts memory), so use `Poll` or `Epoll` for those.

### Time

`Gmtime`, `Timegm` and `Strftime` are implemented from scratch and need no zone data. `Strftime` supports every standard conversion plus the glibc flags `_ - 0 ^ #` and field widths, and its output is checked against glibc for about 1,100 combinations. `Localtime` and `Mktime` take zone rules from the standard library, so `TZ` must name a zone (`America/New_York`), not a POSIX rule string like `EST5EDT`. Times skipped by a daylight-saving change resolve as in glibc (02:30 becomes 03:30). A time that occurs twice honours the `Isdst` hint and otherwise takes the first occurrence, which is the one place glibc itself is not deterministic.

### Processes and signals

- There is **no `Fork`**. A raw `fork` in a multi-threaded Go program leaves the child with one thread and no working scheduler, so its first garbage collection hangs. `Spawn` (a safe fork+exec) and `Execve` cover what `fork` is normally used for. `System` needs `/bin/sh` on the target, as in C.
- `Signal` handlers run on an ordinary goroutine after the Go runtime receives the signal, so a handler may call anything, including `Printf` and `Malloc`. They are not asynchronous: a handler does not interrupt running code.

## Design notes

- **Memory.** `Malloc` takes memory from `mmap`, outside the Go heap, so the garbage collector never sees it. Release it with `Free`. Small blocks use power-of-two size classes carved from 1 MiB arenas, with sharded free lists so goroutines rarely contend. Large blocks (over 64 KiB) get their own mapping, are resized with `mremap`, and a few recently freed ones are cached to skip the `mmap`/`munmap` round trip. Everything is 16-byte aligned. `Free` detects double frees and pointers that did not come from `Malloc`, and aborts with a message. Run `make bench` to measure it.
- **Buffered I/O.** Streams buffer in user space. `Stdout` is line-buffered on a terminal and fully buffered otherwise, and `Stderr` is unbuffered. **End your program with `golibc.Exit`** (or `Fflush(nil)`). Returning from `main` or calling `os.Exit` will not flush golibc's buffers.
- **Syscalls.** Everything goes through the standard library's `syscall` package. The only difference from C is that arm64 has no `open` or `unlink`, so those use `openat` and `unlinkat` on every architecture.
- **Sorting.** `Qsort` is an introsort: median-of-three quicksort, insertion sort for short ranges, and a heapsort fallback that bounds the worst case at O(n log n). No allocation, not stable.
- **errno.** C's `errno` is thread-local, and Go has no goroutine-local storage, so a faithful one cannot exist. The library never depends on it internally (each syscall has a raw form returning `(result, errno)`, which stdio and the allocator use). `GetErrno` is a single atomic value: no data race, but a failure in another goroutine can replace it before you read it. When that matters, check return values.

## Limitations

- `GetErrno` is process-wide, not per-goroutine (see [Design notes](#design-notes)). The allocator is goroutine-safe, but a `File` is not.
- No locale support, wide characters, `Fork`, name resolution (`Getaddrinfo`, DNS), or `%a`/`%p` in the printf and scanf families.
- `math` delegates to Go's standard library rather than reimplementing it.

See the [roadmap](ROADMAP.md) for what is still missing and the planned order of work.

## Platform support

| Platform | Status |
|---|---|
| linux/amd64 | Supported, tested in CI |
| linux/arm64 | Supported, tested in CI |
| macOS, Windows | Not supported. The package fails to compile with a single explanatory error |

The package talks to the Linux kernel directly, so on macOS use an IDE build setting of `GOOS=linux` and run it in Linux (Docker works well).

## Development

```sh
make help     # list targets
make check    # gofmt, vet, and tests on linux/amd64 and linux/arm64 (uses Docker)
make bench    # allocator benchmarks (in a Linux container)
make demo     # build the example and run it in an empty scratch container
make golden   # regenerate the printf, scanf, strftime and time-zone golden files from real glibc
```

CI runs on native amd64 and arm64 runners and also fails the build if a dependency or any cgo is introduced.

```
.
├── pkg/golibc/          the library (flat package: one namespace, like libc)
│   ├── *.go             implementation

├── scripts/             maintenance scripts (golden-file generator)
├── .github/workflows/   CI
├── Makefile             check, test, demo, golden
└── README.md, LICENSE
```
