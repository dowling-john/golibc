# golibc

[![CI](https://github.com/dowling-john/golibc/actions/workflows/ci.yml/badge.svg)](https://github.com/dowling-john/golibc/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/dowling-john/golibc/pkg/golibc.svg)](https://pkg.go.dev/github.com/dowling-john/golibc/pkg/golibc)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**A C standard library written in pure Go.** It talks to the Linux kernel through raw system calls. There is no cgo, no libc, and not a single third-party module.

Programs built on it compile with `CGO_ENABLED=0` into one static binary that needs **nothing installed on the target system** except a kernel: no shared libraries, no system prep, nothing to drift out of sync.

```go
package main

import (
	"github.com/dowling-john/golibc/pkg/golibc"
)

func main() {
	golibc.Printf(golibc.CStr("hello from golibc, pid %d\n"), golibc.Getpid())
	golibc.Printf(golibc.CStr("pi=%.5f  hex=%#x  [%-6s]\n"), golibc.M_PI, 48879, golibc.CStr("ab"))
	golibc.Exit(0) // flushes stdio
}
```

```console
$ CGO_ENABLED=0 go build -o hello . && file hello
hello: ELF 64-bit LSB executable, ARM aarch64, statically linked
$ ./hello
hello from golibc, pid 1
pi=3.14159  hex=0xbeef  [ab    ]
```

## Why

- **No fragile installs.** Cgo ties a binary to the C toolchain and shared libraries on the machine that builds and runs it. golibc binaries are self-contained and cross-compile with a plain `GOOS`/`GOARCH`.
- **A libc you can read.** Every function is a few lines of Go over a thin syscall layer, which makes it a good base for freestanding programs, code transpiled from C, and learning how libc works.
- **Checked against the real thing.** `printf` is tested against output generated by glibc, not against what the author remembers it does.

## Install

```sh
go get github.com/dowling-john/golibc/pkg/golibc
```

Requires Go 1.23+ and Linux (`amd64` or `arm64`). See [Platform support](#platform-support).

Naming follows C with an initial capital: `strlen` is `Strlen`, `fopen` is `Fopen`. Strings are NUL-terminated `*byte`, memory is `unsafe.Pointer`, and failures return `-1` (or `nil`) with the reason in `Errno`.

### printf

Supports the flags `- + space # 0`, field width and precision (including `*`), the length modifiers `hh h l ll z j t`, and the conversions `d i u o x X c s p f F e E g G %`. Arguments are ordinary Go values:

- Each integer keeps its own Go width. `int32(-1)` printed with `%u` gives `4294967295`, and `int(-1)` gives `18446744073709551615`, unless a length modifier says otherwise.
- `%s` takes a C string (`*byte`) or a Go `string`, and prints `(null)` for a nil pointer.
- `%f`, `%e` and `%g` take `float32` or `float64`.
- Not supported: `%n`, `%a`, wide characters, and positional arguments (`%1$d`).

## Design notes

- **Memory.** `Malloc` takes memory from `mmap`, outside the Go heap, so the garbage collector never sees it. Release it with `Free`. Small blocks use power-of-two size classes carved from 1 MiB arenas. Large blocks (over 64 KiB) get their own mapping, are resized with `mremap`, and are returned to the kernel on `Free`. Everything is 16-byte aligned.
- **Buffered I/O.** Streams buffer in user space. `Stdout` is line-buffered on a terminal and fully buffered otherwise, and `Stderr` is unbuffered. **End your program with `golibc.Exit`** (or `Fflush(nil)`). Returning from `main` or calling `os.Exit` will not flush golibc's buffers.
- **Syscalls.** Everything goes through the standard library's `syscall` package. The only difference from C is that arm64 has no `open` or `unlink`, so those use `openat` and `unlinkat` on every architecture.
- **Sorting.** `Qsort` is a heapsort: O(n log n) worst case, no recursion, no allocation, not stable.

## Limitations

- `Errno` is a single global, not a per-thread value, so concurrent goroutines can overwrite each other's error. The allocator is goroutine-safe, but a `File` is not.
- No `scanf` family, locale support, wide characters, signals, or process control yet.
- `math` delegates to Go's standard library rather than reimplementing it.

## Platform support

| Platform | Status |
|---|---|
| linux/amd64 | Supported, tested in CI |
| linux/arm64 | Supported, tested in CI |
| macOS, Windows | Not supported. The package fails to compile with a single explanatory error |

The package talks to the Linux kernel directly, so on macOS use an IDE build setting of `GOOS=linux` and run it in Linux (Docker works well).

## Development

```sh
make help     # list targets
make check    # gofmt, vet, and tests on linux/amd64 and linux/arm64 (uses Docker)
make demo     # build the example and run it in an empty scratch container
make golden   # regenerate pkg/golibc/testdata/printf.golden from real glibc printf
```

CI runs on native amd64 and arm64 runners and also fails the build if a dependency or any cgo is introduced.

```
.
├── pkg/golibc/          the library (flat package: one namespace, like libc)
│   ├── *.go             implementation
│   ├── *_test.go        unit tests and runnable examples
│   └── testdata/        printf cases and glibc-generated golden output
├── examples/hello/      a program using only golibc
├── scripts/             maintenance scripts (golden-file generator)
├── .github/workflows/   CI
├── Makefile             check, test, demo, golden
└── README.md, LICENSE
```
